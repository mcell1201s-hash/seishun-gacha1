# 青春ガチャ。

**部活は選べない。青春は選べる。**

学校・野球部/吹奏楽部/美術部がランダムに決まる、スマートフォン向けの青春育成シミュレーションです。育成23行動、3年間で6大会。最後の行動の後に高校最後の大会を迎え、結果確認から卒業アルバムへ直行します。

## 起動とGitHub Pages

ビルド、外部API、ログイン、外部画像・フォント配信は不要です。HTML・CSS・JavaScriptと同梱のSVGだけで動作します。

```sh
python3 -m http.server 8000
```

`http://localhost:8000` を開いてください。ES Modulesを使うためHTMLの直接ファイル表示は避けます。GitHub Pagesは Settings → Pages → Deploy from a branch → `main` / `/ (root)` を選びます。モジュール・素材は相対パスで参照し、リポジトリ名のサブパス配信にも対応します。

## 23行動のカレンダー

| 学年 | 春 | 夏 | 秋 | 冬 | 大会 |
| --- | --- | --- | --- | --- | --- |
| 1年 | T1〜2 | T3〜5 | T6〜7 | T8〜9 | T5 夏季・T9 冬季 |
| 2年 | T10〜11 | T12〜14 | T15〜16 | T17〜18 | T14 夏季・T18 冬季 |
| 3年 | T19〜20 | T21〜23 | — | — | T20 春季・T23 最後の夏 |

旧版の各学年の夏2行動を3行動に増やしています。3年は引退までの春・夏のみです。学年と季節の計算は `js/calendar.js` に統一し、大会と進級の定義は `CONFIG` に置いています。季節の出会い抽選は従来の5機会を対応する時期（T3・8・12・17・21）へ移動しました。恋愛の必要行動数・成功率は変えていません。

処理順は **行動の基本成長 → 恋愛/季節イベント → チームイベント → ケガ → スキル → 大会判定**。大会のない行動は次ターンへ進み、大会時は判定済みの結果を保持して手動確認します。

T9・18の大会終了後は疲労−15、さらにT10・19の進級時に−25。ほかの通常大会も終了時に−15。**最終T23は、その行動の疲労・能力・連携をそのまま判定に使い、大会前後に自動回復を挟まず卒業します。** 卒業は追加の行動ターンではありません。

## 学校・育成

学校の基礎戦力は入学時に0〜200の連続値で決まり、その周回中は固定。育成環境（0〜100）と校内競争（0〜200）は基礎戦力に緩く相関しつつ、独立したばらつきを持ちます。固定の学校タイプはありません。

6コマンドの基本値は `CONFIG.actions` に集約しています。技術・体力・精神の上限200、疲労・連携・好感度の上限100。練習の成長は環境0.8〜1.2倍、適性1.1倍、行動前の疲労補正（60以上0.8倍、80以上0.6倍）を掛けて四捨五入します。能力による成長逓減はありません。

追加イベントはプラス18%、マイナス12%で相互排他。連携の値はイベント抽選確率に影響しません。練習時のケガ確率は通常2%、疲労60以上8%、80以上18%。ケガの効果は疲労+8・精神−3です。

## 部活総合力と大会

```
部活総合力 = clamp(round(基礎戦力 × 0.72 + チーム連携 × 0.45), 0, 200)
大会戦力 = 部活総合力 + 主人公の貢献 + コンディション補正 + ランダム補正
```

係数は旧大会式を維持しました。暫定案の0.75/0.5にすると、学校と連携が高いほど旧式から大きく上がるためです。新たな差は四捨五入による最大0.5だけ。表示した総合力を実際の大会式に一度だけ使い、基礎戦力と連携の別加算は廃止しています。現係数での理論最大は189で、難易度を保つため200への再スケールは行っていません。

総合力は0〜39「弱小」、40〜79「挑戦者」、80〜119「中堅」、120〜159「有力」、160以上「強豪」。呼び方は現在の実戦力の説明であり、学校ガチャの固定属性ではありません。連携によって数値・評価が上下します。主人公の能力やスキルは含めません。

大会は次を別々に判定します。

1. **出場機会**：技術50%・体力25%・精神25%の加重評価＋選考乱数±12と校内競争との差。差が+5以上はレギュラー、−25以上は途中出場、それ以外は控え。
2. **個人成績**：能力評価×コンディション＋個人乱数±24＋スキル。控えは出場なし。
3. **チーム成績**：総合力＋個人貢献＋コンディション×15＋大会乱数±32。個人貢献は個人評価×出場割合×0.28、控えの支援貢献は8×0.28です。ムードメーカーの貢献3.6も個人側に一度だけ加算し、旧式の効果を維持します。

コンディションは `max(0.6, 1 - 疲労/100 × 0.35)`。チームの順位境界は従来どおり175/145/112/80です。個別の対戦相手パラメータは元々なく、順位境界と独立した乱数で判定しています。新たな相手・大会難度の補正は追加していません。

控えで優勝、個人の活躍とチーム敗退の組み合わせも起こります。野球は勝敗数、吹奏楽・美術は賞名を表示します。

## 次の育成目標

ステータス欄に、現在の出場見込み、次の大会までの行動数、優先して磨く能力を表示します。高さ600px以下では短い課題文をノートへ移し、区分と残り行動数を維持します。

ノートには「他の能力が今のままの場合」の能力目安、現在の加重評価と校内競争、前大会の実際の出場区分を表示します。単独能力の上限でも届きにくい場合は複数能力の育成を案内します。予測は本番と同じ選考式で乱数を0とした見込みで、スキル・交際の大会バフを反映します。本番の抽選があるためレギュラー入りを確約しません。

講評は疲労・連携・不足能力・控えなど、実際に該当する条件の中から選択します。同じ課題だけを繰り返さず、各条件に3表現を用意しています。前大会の記録と比べて出場区分が上がった、連携の基準を越えた、能力が育った場合はその事実を短く添えます。順位を変えるための「同順位回避」は行っていません。

## 恋愛・スキル・トロフィー

恋愛は任意です。交流50%、季節イベント8%で出会い、好感度20から開始。デート+20、60以上で自動告白（85%）。交流→デート→デートの最短3行動で交際できます。

| 相手 | 交際成立時の一度限り効果 | 交際後 |
| --- | --- | --- |
| 春野こはる・応援 | 精神+8、疲労−10 | 各行動25%で疲労−8、大会の精神評価+12 |
| 日向ひまり・努力家 | 技術+8、精神+3 | 練習30%で技術+3 |
| 風見なぎ・自由奔放 | 精神+12 | 20%で精神+5、10%で−3、デート10%で一度限りの覚醒 |

交際後のデートは任意で、しないだけで別れません。デート50%で疲労−12、35%で思い出。交際後デート2回以上・思い出1個以上・好感度80以上で特別な卒業エンディングになります。告白失敗後、練習2回以上から12%の覚醒抽選。再告白・別の相手との再遭遇は未対応です。

努力家・集中力・勝負強さ・鉄人・ムードメーカーの永続スキル5種と、大会/成長/恋愛/逆境/隠しのトロフィー12種を維持しています。「天才」属性はありません。定義・数値は `js/config.js` を参照してください。

## スマホUIと行動演出

ステータスとコマンドの空白は `margin-top:auto` が残り高さを吸収していたことが原因でした。現在は通常の縦積みで間隔10pxとし、余りは画面下部へ残します。背景も高さを増やして余りを吸収しません。`100svh` を最小高さの基準にしてアドレスバーの変動に伴う不自然な中間余白を防ぎ、セーフエリアを確保します。高さ不足時は読みやすさを優先して縦スクロールへフォールバックします。

コマンドは3列×2段。日誌・スキル・行動の説明・目標・大会予定は青春ノートにまとめています。自作SVGの背景、部活アイコン、相手の顔、走る生徒の23ターンゲージを維持しています。素材の差し替えは `assets/pixel/README.md` を参照してください。

通常は **300msのアイコン演出 → 1500msの結果 → 次ターン表示**、合計約1.8秒。タップでスキップでき、重要イベントはタップ待ちです。結果は実際の前後差（疲労・連携・好感度を含む）を表示します。描写は部活別・行動回数で切り替え、ゲームの乱数列を消費しません。

判定は一度だけ実行し、表示用タイマーは再判定しません。連打防止・タイマー解除・世代チェック・ページ中断/復帰・モーション低減に対応しています。大会結果と卒業も手動確認です。

## 卒業の回想・保存データ

卒業時は、初期/卒業時能力、最終出場区分、最高成績、6大会、獲得スキル、相手との関係、結末、トロフィーを保存します。回想は実際の大会記録・成長・重要イベントから代表例を選び、起きていない勝利・交際・ケガ・覚醒を作りません。最終大会結果を確認するとそのまま卒業画面が表示されます。

保存キー `seishun-gacha.history.v1` は維持し、新しい卒業記録の形式だけversion 3（23ターン版）にしました。旧版の記録を上書き・削除・ターン番号変換しません。アルバムに「旧24ターン版」と表示し、当時記録されていなかった初期能力・回想は復元できない旨を案内します。旧トロフィーも保持します。最大50件・同じ周回の重複保存防止は従来どおりです。

育成途中の保存・再開は従来どおり未対応です。演出途中の再読み込みは安全にタイトルへ戻り、未卒業の結果を保存しません。保存無効/容量不足の場合は卒業時に案内します。

## 構成と検証

- `js/config.js`：カレンダー・育成・大会・総合力・恋愛・スキル・トロフィーの定義
- `js/calendar.js`：学年・季節・大会時期の統一窓口
- `js/development.js`：総合力、選考評価、次の育成目標
- `js/game.js` / `js/contest.js` / `js/coach.js`：育成・遷移、大会判定、講評
- `js/graduation.js`：実際の重要イベントの記録と回想・卒業結果
- `js/state.js`：状態初期化、互換性を保った保存・読込
- `js/view.js` / `js/presentation.js`：UIと素材
- `js/turn-feedback.js` / `js/turn-flow.js` / `js/app.js`：演出・操作・タイマー管理

Node.js 22以降（推奨24）、外部パッケージなし：

```sh
node --test tests/*.test.mjs
node tools/check-balance.mjs > /tmp/seishun-balance.json
```

バランス検証は旧式との24万大会の同条件比較、弱小・中堅・強豪の各12,000大会、3部活×3基礎戦力×恋愛有無×100シード＝1,800周の完走を行います。結果は `docs/balance-report.json`、解釈は `docs/balance-report.md` に保存しています。

NODE_PATH=/tmp/seishun-browser/node_modules node tests/browser.cjs

ブラウザテストは既定で `/usr/bin/chromium` を使い、別の場所は `CHROMIUM_PATH` で指定できます。スクリーンショットは `/tmp/seishun-*.png` へ出力します。Android実機・アプリ内ブラウザ固有の表示と、今回の変更を公開サイトへマージした後の確認は別途必要です。
