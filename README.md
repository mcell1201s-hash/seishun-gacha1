# 青春ガチャ。

**部活は選べない。青春は選べる。**

スマートフォン縦画面を中心にした高校3年間の育成シミュレーションです。野球部・吹奏楽部・美術部から所属が決まり、育成・大会・任意の恋愛を経て卒業します。1周5〜8分を目標にしていますが、現在は短いテキスト中心のため操作速度によって変わります。

## 起動・公開

外部API、サーバー側処理、ログイン、ビルド、依存パッケージは不要です。リポジトリのルートで以下を実行してください。

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。ES Modulesを使うため、HTMLの直接ファイル表示は避けてください。GitHub Pagesでは Settings → Pages → Deploy from a branch → `main` / `/ (root)` を指定します。相対パスを使うためリポジトリ名を含むサブディレクトリでも動作します。画像もローカル配信で、外部サービスを必要としません。

## 進行・育成

| 学年 | ターン | 大会（育成行動後） |
| --- | --- | --- |
| 1年 | T1〜8 | T4、T8 |
| 2年 | T9〜16 | T12、T16 |
| 3年 | T17〜20 | T18、T20（最終大会・引退） |
| 引退後 | T21〜24 | エピローグのみ |

各行動は **基本成長 → 恋愛・季節イベント → チームの追加イベント → ケガ抽選 → スキル獲得 → 大会自動判定（該当時）** の順です。結果を表示した後、大会画面を閉じると **大会結果確定・疲労回復 → 次ターン・進級回復** が発生します。表示中に結果を再抽選しません。大会や告白のために追加の行動は消費しません。

学校の基礎戦力は0〜200の連続値、育成環境と校内競争は基礎戦力に緩く相関しつつ独立したばらつきを持ちます。固定の学校タイプはありません。適性は対応する練習能力の成長1.1倍です。

育成コマンドは基礎練習、特訓、チーム練習、休養、交流、デートの6種類を維持しています。練習の能力成長は環境補正0.8〜1.2倍、適性補正、行動前の疲労補正（60以上0.8倍、80以上0.6倍）を掛けて四捨五入します。能力による成長逓減はありません。能力上限200、疲労・連携・好感度上限100。大会後は疲労−15、T9・17の進級時は−25。

基本成長は必ず適用し、追加イベントはプラス18%、マイナス12%で相互排他です。連携はイベント確率に影響しません。練習時のケガ確率は通常2%、疲労60以上8%、80以上18%。ケガは疲労+8・精神−3です。

## 大会の3つの判定

`js/config.js` の `CONTEST` に重み、閾値、ノイズ幅、部活別の結果文を集約しています。

1. **出場機会**：技術・体力・精神の加重評価（0.5 / 0.25 / 0.25）＋選考乱数と、校内競争水準の差でレギュラー・途中出場・控えを判定。
2. **個人成績**：能力評価 × 疲労によるコンディション＋独立した個人乱数＋スキル。控えは「出場なし」とし、架空の個人活躍は付けません。
3. **チーム成績**：基礎戦力 × 0.72＋連携 × 0.45＋主人公の貢献 × 0.28＋コンディション × 15＋独立したチーム乱数。貢献は個人評価に出場機会を反映し、控えにも小さな支援貢献があります。

選考・個人・チームは別々の乱数を使います。強い学校なら控えでも優勝、弱い学校なら個人が活躍しても初戦敗退が起こります。恋愛をしなくても優勝可能です。吹奏楽・美術は優勝相当の賞名で表現し、野球だけ勝敗数も表示します。

大会画面にはチーム成績、出場機会、個人成績、部活別の描写、監督・顧問の講評を表示します。講評は高疲労、低連携、不足能力、出場状況の順に確認し、内部数値や計算式は画面に表示しません。

## 恋愛・覚醒

未遭遇 → 知り合い（好感度20）→ 親密（40）→ 交際中 → 卒業時の結末。

- 交流は50%で出会い。交流以外でもT3・7・11・15・19の季節イベントで8%の出会い抽選があります。交流と季節抽選は重複させません。
- 出会い時に相手を3タイプから抽選。デートは好感度+20、精神+2。
- 好感度60以上のデートで自動告白（成功率85%）。別のターンは使わず、交流→デート→デートの最短3行動で交際可能です。
- 交際成立ボーナスは一度のみ。その行動では継続効果を重ねず、次の行動から適用します。

| タイプ | 成立時 | 交際後 |
| --- | --- | --- |
| 春野こはる・応援 | 精神+8、疲労−10 | 各行動25%で疲労−8、大会の精神評価+12（永続能力には加算しない） |
| 日向ひまり・努力家 | 技術+8、精神+3 | 練習30%で技術+3 |
| 風見なぎ・自由奔放 | 精神+12 | 各行動20%で精神+5、10%で−3（相互排他）、交際後デート10%で一度限りの覚醒 |

ひまりは金髪系ショートボブ、柔らかな表情のオリジナル女子高生。現在のUIでは `assets/pixel/face-diligent.svg` の専用ドット絵を表示します。以前の `assets/himari.png` も保持しています。いずれも本プロジェクト用のオリジナル素材で、既存作品の衣装や固有デザインは使っていません。

交際後のデートは任意で、デートしないだけで別れません。デート50%で疲労−12、35%で特別な思い出を獲得。交際後デート2回以上・思い出1個以上・好感度80以上で特別な卒業エンディングになります。通常の交際エンディングもあります。

告白が失敗すると失恋になり、その相手へのデートを閉じて部活ルートへ進みます。このプロトタイプでは再告白・別の相手との再遭遇はありません。失恋後に練習を2回以上重ねると、以降の練習ごとに12%で一度限りの覚醒（技術+10・精神+12）を抽選します。失恋も覚醒も確定ではありません。自由奔放タイプとの覚醒も同じ成長量で、失恋覚醒とは別に一度までです。

## 永続スキル・トロフィー

スキルは練習回数条件を満たすと、該当練習ごとに抽選します。獲得した行動の基本成長には遡って適用せず、その後の行動・大会で効果を発揮します。

| スキル | 主な獲得行動 | 効果 |
| --- | --- | --- |
| 努力家 | 基礎練習 | 練習の技術成長+1 |
| 集中力 | 特訓 | 大会個人評価+8 |
| 勝負強さ | 特訓・チーム練習 | 大会精神評価+10 |
| 鉄人 | 基礎練習 | 練習疲労0.8倍、ケガ確率半減 |
| ムードメーカー | チーム練習 | 大会連携評価+8 |

大会・成長・恋愛・逆境・隠しの5分類、全12トロフィーを実装しています。優勝、控えで優勝、個人活躍、能力成長、スキル収集、交際、特別エンディング、基礎戦力60以下でベスト8相当以上、失恋、2種類の覚醒などを評価します。条件と定義は `TROPHIES` に集約。プレイ中に達成した条件は保持し、卒業時に一覧を表示します。

## 青春アルバム・保存

卒業時に学校、部活、能力、6大会の詳細、スキル、恋愛エンディング、獲得トロフィーをlocalStorageへ最大50件保存します。タイトルの「青春アルバム」で各記録をタップすると詳細を閲覧できます。初回プロトタイプの古い卒業記録も保持し、詳細がない項目はその旨を表示します。

保存が無効でもプレイできますが卒業時に保存失敗を表示します。端末・ブラウザ間の共有と育成途中の再開は未対応です。再読み込みするとタイトルに戻ります。

## 構成・検証

- `js/config.js`：ゲームバランス、部活・恋愛・スキル・トロフィー定義
- `js/random.js`：乱数の集約。テストでは乱数源を注入
- `js/state.js`：初期状態、保存・読み込み
- `js/game.js`：育成処理、24ターンの遷移
- `js/contest.js`：出場・個人・チームの大会判定
- `js/relationships.js`：出会い、交際、覚醒、スキル、恋愛エンディング
- `js/trophies.js`：トロフィー達成条件の評価
- `js/view.js`：表示、`js/app.js`：ユーザー入力との接続

Node.js 22以降（推奨24）で外部パッケージなしで実行できます。

```sh
node --test tests/*.mjs
```

15テストで大会結果の独立性、恋愛各タイプ、最短交際、ボーナスの一度限り適用、失恋・覚醒、スキル、保存、旧記録の互換性を検証。100通りの乱数シードで同じ育成選択による完走と結果の違いも確認します。

Chromiumで入学→交際→20行動→6大会→4エピローグ→卒業→アルバムの実操作、再読み込み後の記録保持、画像読み込み、JavaScriptエラーがないこと、320/390/1280pxで横方向のはみ出しがないことを確認しています。

ブラウザ確認の再実行手順（Playwrightは任意の検証用依存で、ゲーム自体には不要）：

```sh
npm install --prefix /tmp/seishun-browser --cache /tmp/seishun-npm-cache playwright --no-audit --no-fund
NODE_PATH=/tmp/seishun-browser/node_modules node tests/browser.cjs
```

ブラウザテストは別プロセスでHTTPサーバーを起動してから実行してください。既定のChromiumは `/usr/bin/chromium`、別の実行ファイルは `CHROMIUM_PATH` で指定できます。スクリーンショットは `/tmp/seishun-*.png` に出力します。


## レトロなドット絵UI（Pixel Edition）

ゲームロジック・確率・学校ガチャ・24ターンの大会表・保存形式は変更せず、表示を刷新しています。ネイビーとクリーム色を基調に、青・緑・ピンクで部活や行動を区別します。外部フォントや画像配信には依存しません。

- 季節の高校背景に、半透明の学年・季節ウィンドウと部活中心の情報パネルを重ねます。
- 育成中は各学年の2ターンごとに春・夏・秋・冬。3年生の育成はT17〜20で春・夏まで、引退後はT21秋・T22冬・T23〜24春とし、最後の春に卒業します。これは表示上の季節割り当てのみです。
- ターンゲージ上の男子生徒が1〜24の位置に移動。数値・大会の点・進級の区切りでも位置を確認できます。常時アニメーションは使いません。
- 相手がいるときだけ季節ウィンドウの下に顔・名前・関係性を表示。デートにも同じ相手の顔を表示します。詳細は「ふたりのメモ」を開いて確認できます。
- コマンドは3列×2段、ステータスは2列。スキルは折りたたみ表示です。部活アイコン、チーム練習のバッジ、大会会場は部活ごとに切り替わります。
- 入学結果はカード形式で表示。短い段階的な出現演出は「動きを減らす」設定で無効になります。
- 大会は結果を大きく表示し、監督・顧問の顔と講評を添えます。卒業結果と過去の記録はアルバム風に表示します。

素材の参照・季節割り当ては `js/presentation.js`、自作素材は `assets/pixel/`、再生成用の任意スクリプトは `tools/generate_pixel_assets.py` に分離しています。素材の一覧と差し替え方法は `assets/pixel/README.md` を参照してください。Pythonは素材を作り直す場合だけ必要で、静的サイトとしてはそのまま配信できます。

追加のUI検証（HTTPサーバーと上記の任意Playwright環境を起動済みの場合）：

```sh
NODE_PATH=/tmp/seishun-browser/node_modules node tests/pixel-browser.cjs
```

320/390/540/1280px、3部活、10個のターン・季節表示の計120組み合わせで横はみ出し、3列配置、タッチ領域、能力数値、ターン更新、未遭遇時の非表示とデート無効を確認。相手3タイプの顔の切り替え、走者の位置、監督の顔、モーション低減、GitHub Pages形式のサブパスでの実読み込みも検証しています。既存の大会・恋愛・卒業・保存までのブラウザ検証と、ゲームロジックの15テストも通しています。
